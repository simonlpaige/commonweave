# Map discovery and planning design

Preserve the current botanical paper/moss palette and Instrument Serif /
Source Serif typography. Start with a person's problem and place, then a
diagram of the roles they need. Map, list and compact sidebar share filters.

The sequence is conceptual: food experience → space/land → shared ownership,
for example. Users choose organizations for roles; none is preselected. The
diagram remains a proposed plan, not evidence of capability or collaboration.
Missing roles stay visible and candidate paging reaches beyond the preview.
Users can download their chosen plan with record links, questions and space
for notes. Choices are held only in the current page; downloading saves them.

All current pins lack coordinate precision. Use recorded city/country names,
not distance or service-radius ranking. Source-backed tiers are metadata,
not endorsements. Documented relationships need non-derived provenance and
an attributable public URL; other links remain suggestions.

List view is an alternative to pins and a fallback for failed map rendering.
Mobile Find exposes the same controls. Reset clears filters and plan choices;
filter changes dismiss excluded detail. Clusters count the same filtered
records as points. Controls need labels, focus visibility, and result feedback.

Tests: `assets/js/map/pathways.test.cjs`, plus desktop/390px mobile browser
review. See the overall review report for observed checks and limitations.
