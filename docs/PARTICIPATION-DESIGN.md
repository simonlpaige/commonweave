# Participation and directory design

The existing public brand in `assets/css/brand.css` is canonical: paper
`#F2EBDC`, ink `#16201A`, moss `#2F4A33`, muted ink `#5A6A5C`, and clay
`#B4593A`. Instrument Serif carries headings; Source Serif 4 carries prose.
The older forest-dark defaults in UI-COMPONENTS.md do not match the current
rendered home and directory pages.

Keep this identity. Participation should feel like adding a field note:
one short form, a readable preview, and an explicit next action. Left-align
labels and body copy, use a narrow reading column alongside the form on
desktop, and stack on mobile. No automatic motion or decorative counters.

The form prepares a draft on the device. It offers a file for anyone and a
GitHub review link for contributors with an account. Neither a draft nor a
self-asserted affiliation changes the directory. Do not claim an inbox,
private submission channel, response deadline, or verification service
exists when none has been established. Explain public issue visibility
before the user opens GitHub. Location reduction and removal need no proof
of ownership; sensitive details must never be requested.

Directory repairs preserve existing cards while making search scope,
loading failures, sources, and correction links explicit. A result count
describes the loaded export, not independent verification.
