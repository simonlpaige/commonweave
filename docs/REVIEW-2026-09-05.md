# Commonweave review and implementation — 5 September 2026

Commonweave can become useful by helping people assemble the roles needed to
solve a specific local problem, then checking whether the resulting leads
actually help. The immediate bottleneck is evidence and usability, not the
number of organizations collected. This change provides that starting point;
it does not demonstrate adoption, successful referrals, or confirmed partners.

## Most consequential findings

1. Search advertised 168,650 records in 183 countries/territories; the available
   files contain **144,731 records across 156 nonempty ISO buckets**. The index
   now matches the files. Search, downloadable release and map are distinct
   dated snapshots, not one synchronized directory.
2. **158,706 of 158,715 release records lack a usable verification date.**
   Structural auditing is not individual fact-checking. Website, source and
   description gaps need an evidence queue, not an invented verification badge.
3. All **29,423 map points lack coordinate precision**, 9,843 have invalid tier
   values, and **16,397 of 20,474 edges reference missing endpoints**. Current
   pins cannot support travel-distance rankings or claims that organizations
   work together. The UI discloses limitations and excludes invalid tiers.
4. Geographic concentration and broad category matches distort discovery.
   A cooperative may operate an energy service without advising a new food
   cooperative. Recorded locality can also be wrong. Planning choices remain
   research leads until checked with the organizations.
5. Existing named organizations have their own contribution processes and
   data-reuse terms. A name in Commonweave is not consent to a partnership.
   Useful corrections and small upstream contributions give a stronger reason
   to engage than a generic invitation to endorse the framework.

## Participation pilot and next work

Use the [operating model](../FRAMEWORK-OPERATING-MODEL.md) for the proposed
30-day pilot: ten consenting practitioners, one locality and problem,
comparison with their existing search process, and a fixed maintenance budget.
The food-project pathway is a practical first hypothesis. Record time to a
useful lead, accepted corrections, practitioner return visits, declined or
failed referrals, and maintenance time. Measure these before claiming traction.

Start with the [five-record OFN correction packet](participation-ofn-corrections-2026-09-05.md).
It has release IDs, observed old values, official sources and explicit unknowns.
The matching [pending proposals](../data/proposals/ofn-field-review-2026-09-05.json)
validate without writing data. Review the previous OFN conversation before any
contact. Other organization-specific offers are scoped in the outreach plan;
most still need their own concrete artifact before a message is ready.

The next maintainer task is to select the current canonical DB and build one
coherent release in isolation. Acceptance criteria:

- Search, map, edges and downloadable release derive from the same input hash;
  every published endpoint resolves to an organization ID in that release.
- Invalid source tiers are corrected from canonical evidence, without treating
  NTEE activity codes as trust labels or promoting candidates automatically.
- Every pilot-facing record has a checked identity, source, operating area,
  role, participation route and visibility preference.
- Rendered enriched claims retain their field-level evidence, review date and
  decision. Database evidence events are now saved, but full propagation into
  search/map detail remains unfinished.
- Pilot practitioners can distinguish a documented relationship, their own
  proposed plan, and a category match; failed matches remain measurable.

## Validation and practical limits

Local checks passed: **25 JavaScript tests and 33 Python tests**, search metadata
reconciliation, generation of the 13 observable circuit briefs, validation of
the five pending OFN proposals, and the full public-export audit. Circuit
metadata still declares 76 groups while containing 13; this warning is retained.
The new CI workflow repeats the checks and attaches its audit output.

Browser review covered map goal/country selection, explicit choice and removal,
reset, invalid-city feedback, candidate paging, and desktop/390px/520px layouts.
The 481–600px control gap was repaired. Directory review covered country/state
loading, empty results, missing-file recovery, reset, safe links and mobile
layout. Participation review covered draft generation, edit invalidation,
evidence requirements and optional-evidence protection requests. Browser checks
are a local Chromium smoke test, not a full accessibility or cross-browser audit.

This work is prepared on a separate branch and clone. The original checkout's
staged deletions are preserved. No live database was replaced, no source records
were mass-purged, and no organization was contacted. Changes need review and
publication before they affect commonweave.earth. The five OFN proposals still
require record review and canonical application; their inclusion is not a
claim that those corrections have already reached the live directory.
